## Why

semver is published as CommonJS only. Graft is ESM-only and validates itself by keeping
its own CommonJS dependencies converted to native ESM, so that nothing CommonJS loads from
them in this repo. semver is also required by pacote's CommonJS dependencies (for example
`npm-pick-manifest`), so the conversion has to stay `require()`-compatible.

The variant is generated by `tools/cjs-to-esm/make-variant.mjs` from the pristine tarball
and is a whole-package conversion: every `.js` file becomes an ES module, and package.json
gains `"type": "module"`.

## Invariants

- Every semver module that loads, through `import` or `require()`, is evaluated as ESM.
  Nothing from the package loads as CommonJS.
- `import semver from 'semver'`, `import * as ns from 'semver'`, and `require('semver')`
  all expose the same API as the pristine release: the same keys, with named exports for
  each.
- Deep CommonJS requires used by other packages keep returning the old values:
  `require('semver/functions/satisfies')` is the function, and
  `require('semver/classes/range')` is the `Range` class.
- Behavior is identical to the pristine CommonJS release across a corpus of versions and
  ranges, for every public function and class (differential test).

## Where to look

Every `.js` file in the package (`index.js`, `classes/`, `functions/`, `ranges/`,
`internal/`, `bin/`, `preload.js`) plus the top-level `package.json`. The only real
cross-file subtlety is the `Range` and `Comparator` classes. They require each other at the
bottom of their files, after defining the class, to break a load-order cycle.

## Anchors

- `package.json#1`: inserts `"type": "module"` just before the `"files"` array. The array
  is chosen as the anchor because the hunk's context then never includes the `"version"`
  line, which changes every release.
- One hunk group per `.js` file: the converter replaces top-level `require()` statements
  with imports, prepends the `module`/`exports` shim, and appends the export block. Each
  file's hunks are anchored on that file's `require` lines and its final
  `module.exports = …` statement. These are the parts of semver's files that change least.
  A file whose requires change upstream misses. `graft sync` then reruns the `generator`
  (the converter) for the new version and keeps the result only if the oracle passes;
  otherwise it hands the graft to an agent.
