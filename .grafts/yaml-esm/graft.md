## Why

yaml declares `"type": "commonjs"`. Its `exports` map sends Node to the CommonJS `dist/`
build and everything else to `browser/`, an ESM build. Pointing Node at `browser/` is not
a faithful fix. That build turns `!!binary` into a `Uint8Array` instead of a `Buffer`, and
reports warnings with `console.warn` instead of `process.emitWarning`. This graft converts
the Node build itself (`dist/`) to native ESM in place, so Node keeps the Node behavior
with no CommonJS. It is part of Graft's dogfood validation (see semver-esm).

The variant is generated by `tools/cjs-to-esm/make-variant.mjs`. The `dist/*.mjs` CLI files
and `browser/` are already ESM and are left untouched.

## Invariants

- Every yaml module that loads, through `import` or `require()`, is evaluated as ESM.
- `import YAML from 'yaml'`, the named exports, `require('yaml')`, and `yaml/util` expose
  the same API as the pristine release.
- Behavior is identical to the pristine CommonJS `dist/` build across a corpus that covers
  parse/stringify, documents, anchors and aliases, merge keys, YAML 1.1 types including
  `!!binary` (still a `Buffer`), errors and warnings, and the CST/lexer (differential
  test).

## Where to look

The Node build: every `.js` file under `dist/`, which is TypeScript-compiled CommonJS using
`exports.X = …` and `Object.defineProperty(exports, '__esModule', …)`. Also the `"type"`
field in package.json.

## Anchors

- `package.json#1`: replaces `"type": "commonjs"` with `"type": "module"`. That line sits
  between `"files"` and `"main"`, so its context never includes `"version"`.
- Per file under `dist/`: that file's `require` lines (TypeScript emits them all at the
  top) and its `exports.X = …` block at the end. Both come from the TypeScript compiler,
  so they only change when yaml's module graph changes.
